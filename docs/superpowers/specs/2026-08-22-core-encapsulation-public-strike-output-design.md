# 云台追踪核心封装与打击目标公开输出设计

## 2. 背景

当前系统以 `core/main_tracking_v9.py` 为主入口，包含固定相机检测输入、SORT轨迹管理、RID轨迹与四点匹配、云台视觉测距、距离裁决、云台控制、UI发送及打击端发送等功能。

交付给甲方时，需要让普通现场运维人员无法直接查看核心Python源码，同时保留Windows调试机和Linux RK3588板端的完整运行能力。甲方需要能够在公开源码中维护现有打击端UDP发送，并基于同一个当前打击目标增加一路自己的UDP发送。

核心算法不要求抵抗专业逆向分析。本设计的保护目标是隐藏可直接阅读、复制和修改的Python核心源码，而不是提供强加密、授权管理或硬件级防逆向能力。

## 3. 已确认的需求

### 3.1 必须满足

1. `ENABLE_STRIKE_SEND=True` 保持默认行为。
2. Windows调试机和Linux RK3588板端均需要运行封装后的核心。
3. 以下内容必须封装，不向甲方提供Python源码：
   - SORT完整算法和轨迹生命周期；
   - RID解析、RID轨迹、四点匹配及距离候选；
   - 云台YOLO、MLP、GRU视觉测距及视觉与SORT关联；
   - RID优先、视觉兜底的内部距离裁决；
   - 距离滤波、目标威胁评分、打击目标选择和切换；
   - 云台控制及所有安全门控。
4. UI目标状态和UI定位UDP继续由封装核心内部发送，UI发送源码不公开。
5. 公开源码只负责：
   - 现有13字节打击端UDP；
   - 甲方新增的一路UDP。
6. 公开接口只允许读取当前打击目标的6个业务变量：
   - `target_id`
   - `azimuth_deg`
   - `elevation_deg`
   - `distance_m`
   - `device_longitude`
   - `device_latitude`
7. 公开数据必须与原打击端当前目标完全一致，不提供全部UI目标。
8. 不得修改现有打击端13字节协议。
9. 不得向公开接口、公开日志或甲方终端输出距离来源及可推断距离来源的诊断信息。
10. 甲方发布版不生成文件日志，只保留简化终端信息。

### 3.2 不属于本次范围

1. 不修改SORT、RID、视觉测距或距离模型算法。
2. 不调整目标威胁评分、目标切换阈值、安全框或有效期。
3. 不修改UI `0x02/0x03` 协议。
4. 不修改GT06Z串口协议、云台控制线程所有权或硬件安全条件。
5. 不为甲方设计其新增UDP的最终业务协议；仅提供可直接使用的6个变量和示例发送入口。
6. 不提供抵抗专业逆向、内存抓取或二进制反编译的强安全保证。

## 4. 总体架构

系统拆分为一个编译核心和两个彼此隔离的公开发送程序。

```text
固定相机UDP ─┐
RID串口 ─────┤
云台相机 ────┤
GPS/云台 ────┤
             ▼
      gimbal_core.exe / gimbal_core
      ├─ SORT、RID、视觉测距
      ├─ 距离裁决与滤波
      ├─ 云台控制与安全门控
      ├─ UI 0x02/0x03 UDP发送
      └─ 产生当前打击目标的6个公开变量
                         │
              本机127.0.0.1实时发布
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
      strike_sender.py       customer_udp.py
      现有13字节协议          甲方新增UDP
```

核心与公开发送程序只通过本机回环地址通信，不监听外部网卡。核心只实时发布当前可发送的打击目标，不提供查询全部轨迹、历史结果或内部状态的接口。

两个公开发送程序分别连接核心。甲方新增UDP代码异常、阻塞或退出时，不得影响原打击端、UI、追踪或云台控制。

### 5.2 最小改造原则

不重写现有主循环。实施时只增加明确的最终输出边界，并把现有打击UDP组包与外部发送从核心逻辑中分离。目标选择、角度预测、距离读取和安全判断继续使用当前代码路径。

核心公开事件必须在当前实际准备执行 `STRIKE_SEND` 的最终位置产生，而不能从更早的候选选择阶段产生。这样可以保证公开结果已经通过全部既有安全条件。

### 5.3 继续保留在核心内部的发送

- UI目标状态 `0x02` UDP
- UI设备定位 `0x03` UDP
- 任何核心内部硬件通信

这些发送源码、输入字段和中间状态不向甲方公开。

## 7. 公开数据契约

### 7.1 唯一公开回调

```python
def on_strike_target(
    target_id,
    azimuth_deg,
    elevation_deg,
    distance_m,
    device_longitude,
    device_latitude,
):
    ...
```

公开层不得得到其他业务字段。

### 7.2 字段定义

| 字段 | 类型 | 单位/坐标系 | 说明 |
| --- | --- | --- | --- |
| `target_id` | `int` | 0至255 | 当前打击目标的稳定UI ID |
| `azimuth_deg` | `float` | 地图绝对方位角，北0°、东90° | 与原打击包相同的最终预测方位 |
| `elevation_deg` | `float` | 度 | 与原打击包相同的最终预测俯仰 |
| `distance_m` | `float` | 米 | 核心内部完成裁决与滤波后的最终距离 |
| `device_longitude` | `float`或`None` | WGS-84经度 | 当前设备位置经度 |
| `device_latitude` | `float`或`None` | WGS-84纬度 | 当前设备位置纬度 |

设备位置暂不可用时，经纬度均为 `None`。该情况不阻止原13字节打击包发送，因为原协议不包含设备位置。

### 7.3 不公开的元数据

以下信息可由核心内部用于通信可靠性，但不得作为公开回调参数、公开对象属性或终端字段提供：

- 消息类型
- 协议版本
- 消息序号
- 生成时间
- 过期时间
- 设备位置有效标志
- 核心运行实例ID

公开连接只接收实时流。连接断开期间的数据直接丢弃，重连后从下一条新结果开始，因此公开层不需要持有或判断上述元数据。

### 7.4 严禁公开的来源信息

不得通过字段名、字段值、日志、异常文本或终端输出公开：

- `distance_source`
- RID身份、RID距离、RID匹配或RID有效期
- 视觉距离、视觉模型名称、视觉临时ID或预热状态
- 两路距离年龄或候选有效性
- 来源优先级、来源切换或距离仲裁结果
- 距离滤波状态、径向速度和不确定度
- 能直接推断最终距离来源的内部事件名称

公开层统一只使用 `distance_m`。

## 8. 当前打击目标逻辑保持不变

### 8.1 候选条件

一条轨迹必须继续满足当前代码中的全部条件：

- SORT轨迹已确认；
- UI确认和打击确认均已通过，默认至少连续命中5次；
- 轨迹丢失时间不超过 `MAX_LOCK_LOST_SECONDS=1.6s`；
- 存在内部新鲜有效距离；
- 存在新鲜的云台视觉检测框；
- 检测框通过现有安全区域判断。

### 8.2 威胁评分

保留当前评分：

```text
距离分       = max(0, 600 - 距离米数) × 0.1
接近速度分   = max(0, -径向速度) × 2
轨迹稳定分   = log(1 + min(连续命中次数, 20)) × 3
视觉新鲜度分 = max(0, 3 - 视觉结果年龄秒数) × 3
```

当前打击目标总分继续乘以 `1.20` 作为保持系数。

### 8.3 切换规则

- 没有当前打击目标时，立即选择最高分合格目标。
- 新目标必须比当前目标高至少8分。
- 同一个新目标必须连续保持优势至少0.6秒才切换。
- 优势不足或领先目标变化时重新计时。
- 当前目标失效时立即解除；若有其他合格目标则立即选择最高分目标，否则停止输出。

### 8.4 真正输出条件

只有满足当前实际发送条件时，核心才向公开层产生一组6字段数据：

- `ENABLE_STRIKE_SEND=True`；
- 云台已到位；
- 当前打击目标仍有效；
- 视觉框安全且新鲜；
- 距离仍有效；
- 当前发送窗口仍有效。

默认输出频率保持10 Hz。现有1秒发送窗口、0.5秒视觉结果短时保持和0.3秒角度提前量均保持不变。

## 9. 原打击端协议保持不变

公开 `strike_protocol.py` 必须逐字节复现当前协议：

```text
字段                         编码
帧头                         AA 55
帧长度                       0D
目标ID                       uint8
距离                         round(distance_m × 10)，uint16，大端
地图方位                     round(azimuth_deg × 10)，uint16，大端
俯仰                         round(elevation_deg × 10)，int16，大端
校验                         前10字节逐字节XOR
帧尾                         55 AA
总长度                       13字节
```

约束继续保持：

- 目标ID：0至255；
- 距离：0.1至6553.5米；
- 方位：按360°归一化；
- 俯仰：-35°至60°。

设备经纬度绝不写入原打击包。

## 10. 两路公开UDP的一致性与隔离

### 10.1 数据一致性

原打击端和甲方新增UDP均由同一次核心最终输出触发，因此二者的目标ID、方位、俯仰和距离来自同一组不可变值。

甲方新增UDP只能跟随当前打击目标，不能获得其他SORT或UI目标。

### 10.2 进程隔离

`strike_sender.py` 和 `customer_udp.py` 分别运行。任一程序异常不得阻塞另一程序。

核心允许两个本机客户端同时订阅同一实时结果。任何客户端断开时：

- 核心追踪、云台控制和UI发送继续运行；
- 另一客户端不受影响；
- 断开期间不积压结果；
- 重连后只接收新产生的结果。

### 10.3 甲方代码责任边界

甲方可以在 `customer_udp.py` 中定义自己的目标IP、端口和组包格式，但无法要求核心输出额外轨迹、来源或诊断字段。

甲方代码异常只影响甲方新增UDP。原打击端发送程序不得导入或调用甲方业务模块。

## 12. 故障处理

### 12.1 甲方新增UDP异常

- 不影响原打击端UDP；
- 不影响UI发送；
- 不影响追踪和云台控制；
- 终端只显示甲方发送程序的通用错误。

### 12.2 原打击发送程序异常

- 核心追踪、UI和云台继续运行；
- 原打击发送程序自动重连核心；
- 不使用或补发断线前的数据。

### 12.3 核心异常

- 两个公开发送程序立即停止发送；
- 禁止继续使用最后一次目标；
- 核心恢复后只从下一条新有效结果开始发送。

### 12.4 设备位置不可用

- 原打击端13字节UDP继续正常发送；
- 经度和纬度均传递为 `None`；
- 甲方自行决定是否跳过自己的UDP；
- 终端提示限频，且不说明位置或距离数据来源。

## 15. 验证与验收

### 15.1 协议验收

- 相同输入产生的13字节打击包逐字节一致；
- 帧头、长度、缩放、大小端、XOR和帧尾一致；
- 设备经纬度不进入原打击包。

### 15.2 目标行为验收

覆盖并验证：

- 初次选择最高威胁目标；
- 领先不足8分不切换；
- 领先超过8分但不足0.6秒不切换；
- 连续领先超过0.6秒后切换；
- 当前目标失效后立即切换或停止；
- 云台未到位时不输出；
- 视觉框不安全或过期时不输出；
- 轨迹丢失超过1.6秒时不输出；
- 距离无效时不输出；
- 视觉结果短时缺失最多保持0.5秒；
- 默认发送频率保持10 Hz。

### 15.3 两路一致性验收

- 两路对同一次输出使用相同目标ID、方位、俯仰和距离；
- 甲方新增UDP只能看到当前打击目标；
- 甲方程序退出不影响原打击端；
- 原打击程序退出不影响甲方程序、UI和核心；
- 任一程序重连后不补发旧数据。

### 15.4 设备位置验收

- 有效位置时公开WGS-84经纬度；
- 位置不可用时两个字段均为 `None`；
- 位置不可用不阻止原13字节打击包；
- 不公开位置来源。

### 15.5 信息隐藏验收

- 甲方发布包中不存在核心Python源码；
